# MAKE BECOMING — FORGE/0

An evolving **Fracture & Agency Forge**: a generative, browser-local SVG observatory alongside a native C simplicial kernel and an optional private PHP content-addressed journal.

**[Open the observatory](https://makebecoming.vercel.app)** · [Four epochs / fourteen chapters](docs/roadmap.md)

## Chapter 6 increment — Occlusion and regeneration (V2.3)

A separate **OCCLUSION / REGEN** full-switch view reads the public-only `occlusion-public.json` generated by the compiled C kernel. `forge-kernel occlude <verified.jsonl>` first validates all source events, constructs the native compatible-contact graph, and discloses only **4-position bands, compatible links, and macro component counts**; exact origin positions, latencies, boundary positions, event digests, and other sensitive record fields are not present **inside this projection**.

The C operation enumerates a bounded inverse-image set (at most six nodes) satisfying the published bands and compatibility relationships. The browser independently verifies the number and initial candidates using public constraints; selecting a candidate does **not** assert recovery of the original. For the three-event fixture, the inverse image has **45 compatible assignments**. For more than six nodes, exhaustive enumeration abstains.

**Privacy limitation:** the deterministic omission generator, complete example input and full `field.json` are intentionally public elsewhere on the site. Therefore the real coordinates can be inferred from other available information. This chapter demonstrates *non-injective projection semantics*, **not confidentiality, anonymous transport, zero-knowledge proof, or real privacy isolation**. The public-only JSON is unsigned, and its producer verification cannot be independently established from this projection. Future private/public separation must exclude private source blocks and derivation leaks from published artifacts.

Local commands:

```sh
make occlusion
./forge-kernel occlude examples/v2_1_verified.jsonl > occlusion-public.json
python3 tests/test_occlusion.py
```

The existing **OMISSION** and **FIELD** modes remain available. Selecting **Current session** in Occlusion derives the equivalent example with JavaScript rather than running native C on Vercel.

## Chapter 5 increment — multiscale relational field

The **FIELD / MICRO→MACRO** full-switch mode reads `field.json`, an actual static artifact produced by the compiled C kernel from the checked-in, independently hash-verifiable omission fixture. On the hosted site, C does **not** run at request time. At load, the browser verifies the source JSONL hash chain and independently checks all native field positions, contacts, motifs and component grouping. It does not reproduce the native simplicial-boundary calculation in the browser.

For each verified omission event, the field defines an indexed position

`(generation, position) = (sequence - 1, origin_strand)`.

All pairs of earlier and later events are candidate *observational comparisons*. For a later record `i` and earlier record `j`:

`tau = generation_i - generation_j`, `delta = position_j - position_i`.

The invariant `delta * generation + tau * position` has equal values at the two endpoints. A **candidate** becomes *compatible under this demo rule* iff `tau ≤ 3`, `abs(delta) ≤ 6` and the two events' affected-strand sets overlap. The macro regions are connected components of this compatible-contact graph. This compatibility rule is an explicit example policy, not a proven physical law or causal test.

The three-event fixture produces:

| Micro | Meso | Macro | Native R0 simplices |
|---|---|---|---|
| 3 positions | 3 candidate pairs, 1 compatible | 2 regions | 27 vertices, 65 edges, 57 faces, 18 tetrahedra |

The highlighted contact at `tau=2, delta=3` goes from `(2,0)` to `(0,3)` and preserves `3g+2p=6`. This is what the *actual committed example data* provides; the earlier conceptual `(2,1)↔(0,4)` crossing is not falsely substituted into the fixture.

The field offers two distinct data sources:

- **Native C fixture:** checked-in `field.json`, generated by C and cross-checked against verified source input.
- **This session:** current browser-local events mapped using the same declared JS rule. This is not native C execution, and has no remote persistence.

The **OMISSION** mode, including historical/counterfactual separation, SHA-256 JSONL export/import, and local minima, remains available and unchanged.

## Local build / regeneration (Linux / WSL2)

Requirements: C11 compiler, `make`, `libssl-dev`, PHP CLI 8.1+, Python 3.

```sh
sudo apt install build-essential libssl-dev php-cli python3
make
make test
make field
./forge-kernel field examples/v2_1_verified.jsonl > /tmp/forge-field.json
./forge-kernel replay examples/v2_1_verified.jsonl --topology /tmp/forge-topology.jsonl
php runtime/forge-store.php append examples/v2_1_verified.jsonl "$HOME/.local/share/makebecoming"
php runtime/forge-store.php replay "$HOME/.local/share/makebecoming"
python3 -m http.server 8000
```

Then open `http://localhost:8000`, use **MODE → FIELD**, and select **Native C fixture**.

`make field` regenerates the checked-in `field.json` from the verified fixture. The generated JSON is a derived representation, not a signed attestation, IPFS CID, or network-distributed history.

## Data / security boundaries

All example events are simulated, not claims about physical events, quantum hardware, private qualia, or causal observations. The R0 event hashes use a restricted deterministic ASCII/integer canonicalization, **not** full RFC 8785. Static Vercel hosts only HTML, JSONL and JSON output. The native C executable and PHP local journal are not deployed as persistent services.

There are no public peers, wallets, automated token effects, cryptographic execution grants, privacy overlays, or HEX-0 compiler chain in this release. The project remains a developmental instrument rather than a production security boundary.
