# MAKE BECOMING — FORGE/0

An evolving **Fracture & Agency Forge**: a generative, browser-local SVG observatory alongside a native C simplicial kernel and an optional private PHP content-addressed journal.

**[Open the observatory](https://makebecoming.vercel.app)** · [Four epochs / fourteen chapters](docs/roadmap.md)

## Chapter 7 — Global Grants & BECOME (V2.4)

The new **GRANTS / BECOME** full-switch observatory shows an offline, *public demonstration-only* grant and effect receipt. It checks Ed25519 signatures in Web Crypto on a secure origin, validates grant/request hashes, a locally pinned issuer public key, scope, nonce, source HEAD, and cross-references the native signed receipt. This browser mode cannot authorize or execute an effect. Its denial controls are preflight scenarios, not requests to a remote service.

The local C/PHP executor supports one effect type: `relation.assert` between two existing event CIDs. No arbitrary commands, wallets, financial transfers, or external integrations are permitted.

- `src/forge-grant.c`: strict, ordered ASCII protocol (`FORGE-GRANT/1`, `FORGE-EFFECT/1`), Ed25519 issuer signature, separately signed subject request, 256-bit unique nonce, finite validity, one-effect limit, scope and source-HEAD binding. A trusted issuer must match the root pinned in the local journal.
- `runtime/forge-effects.php`: `init-root`, `become`, `audit`. The root is initialized once; `become` verifies authorizations and atomically commits a single local effect under a filesystem lock, with content-addressed grant, request and receipt records. Failed attempts return explicit *noncommitted* rejection receipts.
- `grants/public-demo.json`: a signed test fixture with public keys and committed local example. Its private signing keys were generated in a temporary directory, never committed or deployed.

Quickstart from a clean directory (requires C11, OpenSSL development libraries, PHP, Python, make, and OpenSSL CLI):

```bash
make
make test
php runtime/forge-store.php append examples/v2_1_verified.jsonl /tmp/forge-example-store
python3 -c 'import json; x=json.load(open("grants/public-demo.json")); open("/tmp/demo.fg","w").write(x["grant_text"]); open("/tmp/demo.fe","w").write(x["request_text"]); print(x["pinned_root"])' > /tmp/demo-root.pub
php runtime/forge-effects.php init-root /tmp/forge-example-store "$(cat /tmp/demo-root.pub)"
php runtime/forge-effects.php become /tmp/demo.fg /tmp/demo.fe /tmp/forge-example-store
php runtime/forge-effects.php audit /tmp/forge-example-store
# A second become invocation rejects nonce_already_consumed.
```

Tests include subject/issuer Ed25519 signatures, malicious/expired grants, changed request bytes, trust-root substitution, source-HEAD mismatch, tampered receipts, and concurrent double-consumption (exactly one locally commits). The test suite generates fresh temporary key material using OpenSSL CLI. An isolated browser harness exercises all four modes; environment restrictions prevent browser network navigation, so the test bridges cryptography and should **not** be represented as a full real-HTTPS/WebCrypto acceptance test.

**Security limitations:** this is a single-machine development implementation, not distributed consensus, hardware-backed key management, delegation hierarchy, external side-effect orchestration or network anonymity. Anyone with sufficient local filesystem privileges can undermine the pinned root, journal, or anti-rollback records. Entire-store rollback remains possible without an independently witnessed checkpoint. Rejections are returned as local responses; they are not append-only accepted effects. The Vercel deployment hosts static artifacts only; its native C/PHP code is committed to GitHub but not running as a public execution service.

## Chapter 6 increment — Occlusion and regeneration (V2.3)

A separate **OCCLUSION / REGEN** full-switch view reads the public-only `occlusion-public.json` generated by the compiled C kernel. `forge-kernel occlude <verified.jsonl>` first validates all source events, constructs the native compatible-contact graph, and discloses only **4-position bands, compatible links, and macro component counts**; exact origin positions, latencies, boundary positions, event digests, and other sensitive record fields are not present **inside this projection**.

The same C operation enumerates a bounded inverse-image set (at most six nodes) satisfying the published bands and compatibility relationships. The browser independently verifies the number and initial candidate list using the publicly disclosed constraints; selecting a candidate does **not** assert recovery of the hidden original. For our three-event reference, the inverse image has **45 compatible assignments**, with six inspectable examples. For more than six nodes, the exhaustive enumeration deliberately abstains.

**Privacy limitation:** the deterministic omission generator, the complete source example fixture and the full `field.json` are intentionally public elsewhere on the site. Thus the real coordinates can be inferred from other available information. This chapter demonstrates *non-injective projection semantics*, **not confidentiality, anonymous transport, zero-knowledge proof, or real privacy isolation**. Public-only JSON is unsigned, and its claimed producer verification is not independently attested by that file. Future private/public separation requires excluding private source blocks and all derivation leaks from deployed artifacts.

Local commands:

```sh
make occlusion
./forge-kernel occlude examples/v2_1_verified.jsonl > occlusion-public.json
python3 tests/test_occlusion.py
```

The existing **OMISSION** and **FIELD** modes remain available. Selecting **Current session** in Occlusion derives the equivalent demonstration with browser JavaScript rather than executing C on Vercel.

## Chapter 5 increment — multiscale relational field

The **FIELD / MICRO→MACRO** full-switch mode reads `field.json`, an actual static artifact produced by the compiled C kernel from the checked-in, independently hash-verifiable omission fixture. On the hosted site, C does **not** run at request time. At load, the browser verifies the source JSONL hash chain and independently checks all native field positions, contacts, motifs and component grouping. It does not reproduce the native simplicial-boundary calculation in the browser.

For each verified omission event, the field defines an indexed position

`(generation, position) = (sequence - 1, origin_strand)`.

All pairs of earlier and later events are candidate *observational comparisons*. For a later record `i` and earlier record `j`:

`tau = generation_i - generation_j`, `delta = position_j - position_i`.

The invariant `delta * generation + tau * position` has equal values at the two endpoints. A **candidate** becomes *compatible under this demo rule* iff `tau ≤ 3`, `abs(delta) ≤ 6` and the two events' affected-strand sets overlap. The macro regions are connected components of this compatible-contact graph. This compatibility rule is an explicit example policy, not a proven physical law or causal test.

The three-event fixture produces:

| Micro | Meso | Macro | Native R0 simplices |
|---|---|---|---|
| 3 positions | 3 candidate pairs, 1 compatible | 2 regions | 27 vertices, 65 edges, 57 faces, 18 tetrahedra |

The highlighted contact at `tau=2, delta=3` goes from `(2,0)` to `(0,3)` and preserves `3g+2p=6`. This is what the *actual committed example data* provides; the earlier conceptual `(2,1)↔(0,4)` crossing is not falsely substituted into the fixture.

The field offers two distinct data sources:

- **Native C fixture:** checked-in `field.json`, generated by C and cross-checked against verified source input.
- **This session:** current browser-local events mapped using the same declared JS rule. This is not native C execution, and has no remote persistence.

The **OMISSION** mode, including historical/counterfactual separation, SHA-256 JSONL export/import, and local minima, remains available and unchanged.

## Local build / regeneration (Linux / WSL2)

Requirements: C11 compiler, `make`, `libssl-dev`, PHP CLI 8.1+, Python 3.

```sh
sudo apt install build-essential libssl-dev php-cli python3
make
make test
make field
./forge-kernel field examples/v2_1_verified.jsonl > /tmp/forge-field.json
./forge-kernel replay examples/v2_1_verified.jsonl --topology /tmp/forge-topology.jsonl
php runtime/forge-store.php append examples/v2_1_verified.jsonl "$HOME/.local/share/makebecoming"
php runtime/forge-store.php replay "$HOME/.local/share/makebecoming"
python3 -m http.server 8000
```

Then open `http://localhost:8000`, use **MODE → FIELD**, and select **Native C fixture**.

`make field` regenerates the checked-in `field.json` from the verified fixture. The generated JSON is a derived representation, not a signed attestation, IPFS CID, or network-distributed history.

## Data / security boundaries

All example events are simulated, not claims about physical events, quantum hardware, private qualia, or causal observations. The R0 event hashes use a restricted deterministic ASCII/integer canonicalization, **not** full RFC 8785. Static Vercel hosts only HTML, JSONL and JSON output. The native C executable and PHP local journal are not deployed as persistent services.

There are no public peers, wallets, automated token effects, privacy overlays, or HEX-0 compiler chain in this release. Cryptographic grants exist locally only. The project remains a developmental instrument rather than a production security boundary.
